# Build the Campus · play-test

**Play it:** https://a2-learning-studio.github.io/data-center-build-playtest/

A free, offline, single-page game for a public library panel on data centers. The player is the construction manager building a data center campus on a made-up Georgia site, one phase at a time: site and permits, erosion control and grading, utilities, foundations, shell, MEP, data hall fit-out, commissioning (levels 1–4 during construction, level 5 at the end), and turnover. It has a critical-path schedule, issue cards with trade-offs, a Neighbors panel, a dashboard and an end-of-game debrief that prints. A one-page educator sheet, `educator.html`, goes with it. The game shows facts and trade-offs and does not take a side on data centers.

**Kiosk setup.** For a computer with no network, download `build-the-campus-offline.html` (About links to it, or on a kiosk prints its address) and open it in a full-screen browser. It is the whole game in one file, narration included. For an unattended kiosk, also use the browser's own kiosk or lockdown settings (for example Microsoft Edge kiosk mode): the game starts itself over, but it cannot close other tabs or the print dialog. The web page, `index.html`, is smaller: the first time narration plays, it loads all the narration clips from `voice/en/` at once, the same set in the same order for every player; a clip that fails to load is asked for again only with the rest of any missing clips, at the next narration, never on its own. On the web address, the versioned `sw-build-the-campus-*.js` file (written from `sw.js` by `build.mjs`) saves the page once, from the copy the browser already has (no second download), and keeps the clips once they have loaded (clips that loaded before it took over are asked for once more through it, the same set in the same order), so a reload can still open, with narration, after the connection drops. The saved page also opens when the host answers with an error, or has not answered within 4 seconds. While the kiosk is online, a reload checks for a new build and takes it; the clips that build still uses are kept, and older saved copies are dropped. The address `a2-learning-studio.github.io` is shared with the studio's other projects, and any page there can reach this game's saved copies. The worker therefore holds the SHA-256 of the page, the educator sheet and every clip, and serves a saved copy only when it matches. Such a page could still delete the saved copies or remove the worker, so the game would load from the network again; a kiosk that must not depend on that shared address should use the offline file. In About, the game explains the same setup. GitHub Pages builds with Jekyll; `_config.yml` keeps the sources, `tests/`, the npm and CI files and the test build out of the published site, and publishes the two licence texts in `vendor/`.

**Kiosk checklist.**
- Open the offline file in the browser's kiosk mode, for example `msedge.exe --kiosk "file:///C:/Kiosk/build-the-campus-offline.html?mode=library" --edge-kiosk-type=fullscreen --no-first-run`, or in full screen (F11). `?mode=library` works on the file too and keeps the voice off for every player. Edge kiosk mode runs InPrivate and forgets a ticked Library mode box when it restarts; the address does not.
- Turn off sleep and the screen saver, so the screen stays on between visitors.
- *Print this summary* on the end screen opens the browser's print dialog: connect a default printer, or tell visitors the summary is for the screen only.
- Each morning, check the version badge in the top bar and close any other tabs or windows. The offline file never updates itself: download it again when the web copy shows a newer version.
- With no mode, an idle game starts over after about three minutes, and the end screen clears after about a minute and a half.

**Modes.** With no mode the page is set up for a library kiosk: it starts over after a few minutes without input and saves nothing. What a visitor switches (the voice, Library mode, presenter view, the single-key shortcuts) lasts one game, and About prints its source, contact, educator-sheet and download addresses as plain text, so no tap opens another tab, an email app or a download. `?mode=library` is the same kiosk with the voice off for every game. Add `?mode=class` (a staffed class) or `?mode=home` to the address to stop it clearing itself and to keep the game in progress if the page reloads, until the tab is closed; the intro then names the mode, and About's addresses are links. In those two modes the device remembers Library mode, the voice, presenter view and the shortcut switch under `build-the-campus:v1:` keys; nothing is sent anywhere. Their end screen can also save the game to the device as a results file (*Save results file*: JSON with the choices, scores and timed steps, and no name; *Save as CSV*: one spreadsheet row), and *Open results file* on the intro shows a saved one again, read only. The file is read in the browser and never uploaded; a kiosk offers neither. Printing anywhere but the end screen prints a short note, never a summary. In any mode the address can also set what every game starts with: `?voice=off`, `?view=presenter` and `?keys=off`, joined with `&` (for example `?mode=class&voice=off`).

**Browsers and computers.** Chrome or Edge 108 or later, Firefox 101 or later, or Safari 15.4 or later (Mac, iPad and iPhone); the game needs `<dialog>`, `100dvh` and, for the 3D map, WebGL 2. Where it cannot run (scripts off, or an older browser), the page says so and names these browsers. Most computers, Chromebooks and tablets in use today have WebGL 2 graphics. A screen 1280 × 720 or larger works best; phones show a smaller map. On a computer window up to 900 px tall, the schedule under the map starts as a row of phases, so the map stays large; Show timeline opens its bars (phones and tablets keep the full schedule on its own tab). Without WebGL the panels, the schedule and every decision still work. The game picks less 3D detail on software rendering, older Intel HD and UHD graphics, entry-level ARM graphics (Mali, Adreno 500 and earlier, PowerVR) and small machines; add `?quality=low` or `?quality=high` to the address to override it.

**Presenter view.** For a projector or a large screen: the four-corner button on the map (or the switch in About, or `?view=presenter` in the address) hides the side panel and the schedule so the map fills the screen, and makes every label at least 16 px. On a tablet held upright it makes the map taller and every label at least 16 px; on a phone it makes the map taller. The Build panel and the scores stay. In class and home modes the device remembers the setting; on a kiosk the button lasts one game, and `?view=presenter` starts every game in it.

**Map controls.** Drag to turn; scroll, pinch or + and − to zoom toward the pointer. Zoomed in, a drag (or Shift + arrow keys) moves the view, and right-drag, Shift-drag or two fingers turn it. The buttons on the map do the same, and Reset view brings the whole site back.

## Developer notes

**Build and checks.** CI uses Node 24. `node build.mjs` (`npm run build`) runs the consistency checks and rewrites the built pages. A narration line with no recorded clip is only a warning there, and the game shows it as a caption. `node build.mjs --strict` (`npm run build:strict`) stops on such a line before it writes anything, so use it for a release. `node build.mjs --test` (`npm test`) rebuilds and then runs every script in `tests/`, which takes about 15 to 20 minutes under software rendering. The browser checks need Playwright. `npm ci` installs the version that `package.json` pins, with axe-core for `a11y-check`. Without it, set `PLAYWRIGHT_MODULE` to a playwright or playwright-core folder, and `PW_EXECUTABLE` or `PW_CHANNEL` to use a browser you already have. `SHOTS_DIR` is where screenshots and `build-check`'s temporary copies go.

**CI.** `.github/workflows/checks.yml` runs on every push to `main`, on every pull request, and by hand. It runs `npm ci`, installs Playwright's Chromium and runs `node build.mjs --strict`. The run fails if the committed pages differ from that build, so commit the rebuilt `index.html`, the offline file, `docs/` and the service worker with every source change. It then runs `node build.mjs --strict --test`, which runs all 11 checks in `tests/`: `a11y-check`, `build-check`, `debrief-check`, `feedback-check`, `layout-check`, `offline-check`, `order-check`, `pan-check`, `playthrough`, `session-check` and `wait-path`. `offline-check` serves the web page on 127.0.0.1 for the service worker, which GitHub's runners allow. Screenshots from a failed run are kept for 7 days as the `check-screenshots` artifact. The workflow blocks a merge only once the owners make it a required check for `main` in the branch protection settings.

**Line endings.** `.gitattributes` gives every checkout LF line endings, Windows included. The build also reads its sources as LF, so a CRLF copy builds the same pages with the same CSP hashes. `build-check` builds an LF copy and a CRLF copy and compares them byte for byte.

**Where the site is published.** GitHub Pages publishes the `main` branch from its root folder (`/`) with Jekyll, through the "pages build and deployment" runs. This was checked on 27 October 2026. The live site serves `/LICENSE` and `/LICENSE-CONTENT`, which exist only at the root, and returns 404 for `/docs/index.html`. The Pages settings API (`/repos/a2-learning-studio/data-center-build-playtest/pages`) returns 404 without an admin token, so the setting itself could not be read. The `_config.yml` exclude list is therefore what keeps sources out of the site. `build-check` fails when a new root file is neither excluded there nor on its list of published files. The build also writes the same pages to `docs/` so that either folder can be published, but `docs/` is not served today. Whether to switch Pages to `docs/` or stop writing it is for the owners to decide.

**Another language.** `strings.mjs` has an empty `es` table, so the language button stays hidden and the game is in English only. A partial table works. The game, the captions and `voice.mjs` fall back to English one key at a time (`merge` in `voice-lines.mjs`; `game.js` has the same function). The build lists the missing keys, and it stops if a list has a different length from the English one, if a string replaces a table, or if the table has no `lang` code of its own. A line with no clip in `voice/<lang>/` shows its caption and plays no sound. Clips are never borrowed from English. The language button is on the intro and in the top bar. On a kiosk each new game starts in English, and in class and home modes Start over keeps the chosen language. After a switch these stay in English: the link-preview tags, the 3D map's role description ("3D map") and the educator sheet. A table that renames a phase with a `spoken` name in English (`phases.mep.spoken`) needs its own `spoken`.
